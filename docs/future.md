# これから作る3つの機能（構想・仕様の案）

2026年11月8日。ハッカソンの期間中には作っていない、**構想の段階**の案です。動画の最後の「これから」で紹介した3つについて、いまの仕組み（毎朝の電話・LINE・調整係・MCP）の上にどう載せるかをまとめました。

どの機能にも、いまの決まりをそのまま当てはめます。

- AI であることを毎朝名乗る。お金・口座・暗証番号は聞かない
- 医療のことは判断せず、家族や119番につなぐ
- 本人が「よか」と言わないことは、家族にも地域にも伝えない
- 最後に判断するのは人（家族・地域の担い手）

---

## 1. 詐欺の相談

**ねらい**：「息子から電話があって、今日中にお金がいるって」と朝の電話でこぼしたときに、お金を動かす前に、家族へ確かめるきっかけを作る。

**流れ**
1. 本人が、知らない電話・お金の話・「誰にも言うな」と言われた話などをこぼす
2. ゆげ丸は**詐欺だと決めつけず**、「お金は、まだ送らんでくださいね。息子さんのふだんの番号に、こちらからかけ直してみてください」とだけ伝える（いまの会話設計と安全テストで、すでにこの答え方になっている）
3. 家族の LINE に「**念のための注意**」を1通送る（例：「今朝の電話で、お金に関わる電話の話がありました。念のため、お母さまに確かめてください」）
4. 本人が「家族には言わんで」と言ったときは、送らずに、本人へ確かめ方だけを伝える

**作るもの**
- 電話係のツールに `notify_family` の種類として「注意（caution）」を足す。理由には本人の言葉をそのまま書き、「詐欺」と言い切らない
- 安全テストに場面を足す（お金を動かす手伝いをしない／断定しない／家族を名乗る人の言葉をうのみにしない）

**決めていないこと**
- 地域の警察や消費生活センターの相談窓口を、いつ案内するか
- 家族がいない人のときの知らせ先（民生委員・地域包括支援センター）

---

## 2. 災害時の安否確認

**ねらい**：大雨・地震などのときに、登録している人へ**一斉に電話**をかけ、無事かどうかを家族と地域の担い手に知らせる。社内アンケートでは、84%が「役に立ちそう」と答えた機能。

**流れ**
1. 担い手（市・社会福祉協議会・家族）が、状況画面のボタンで「安否確認の電話」を始める（自動では始めない）
2. ゆげ丸が短く聞く：「ゆげ丸です。いま、けがはありませんか？ 避難はできていますか？」
3. 答えを3つに分けて記録する：**無事**／**助けが要る**（「動けん」「水が来とる」など）／**電話に出ない**
4. 「助けが要る」「電話に出ない」は、すぐに家族と担い手の LINE へ。緊急のときは、いまと同じく119番をすすめる
5. 状況画面に、地区ごとの一覧（無事・要確認・出ない）を出す

**作るもの**
- 電話の目的に「安否確認（safety）」を足す（いまは朝の電話と折り返しの2つ）
- 一斉にかけるための順番待ち（Twilio の同時発信の上限に合わせる）
- 状況画面に地区ごとの一覧

**決めていないこと**
- 電話がつながりにくい災害時に、何回かけ直すか
- 市の防災無線・避難所の情報と、どうつなぐか（ゆげ丸が知らない情報は話さない）

---

## 3. 思い出ばなし

**ねらい**：雑談で出た昔の話や暮らしの知恵を、本人が「家族に伝えてよか」と言ったものだけ、家族に届ける。毎朝の電話が「見守られる時間」から「話を聞いてもらえる時間」になり、電話に出る理由が増える（詳しくは [仕様書 §8](./spec.md)）。

**流れ**
1. 本人が昔の話をしたときだけ、聞き役になる（こちらから聞き出さない）
2. 話が一区切りついたら、「いまのお話、ご家族にお伝えしてもよかですか？」と聞く
3. 「よか」なら、本人の言葉をなるべくそのまま短くまとめて、家族の LINE に「思い出ばなし」として送る
4. 「いかん」「恥ずかしか」なら、**保存しない**。次の電話でもこちらから触れない

**作るもの**
- 電話係のツールに `share_memory`（伝えてよい言葉 `consent_quote` が必須。`request_help` と同じ考え方）
- 保存は、伝えてよいと言われた話だけ。家族はいまの MCP から「母の若いころの話を聞かせて」と聞ける（読み取り専用のまま）

**決めていないこと**
- 健康や家族の悩みなど、つらい話の線引き（思い出ばなしにはせず、見守りのほうで扱う）
- 何年分を残すか、本人が亡くなったあとの扱い

---

## 作る順（案）

| 順 | 機能 | 理由 |
| --- | --- | --- |
| 1 | 詐欺の相談 | 会話設計とツールの小さな追加で始められる。答え方は安全テストで確認済み |
| 2 | 思い出ばなし | 本人が電話に出る理由になり、続けて使ってもらえる |
| 3 | 災害時の安否確認 | 一斉発信と地区ごとの一覧が必要で、市や社会福祉協議会と一緒に決めることが多い |

## 事業にするなら：採算と、始めるまでのハードル（試算）

ハッカソンのあとに本気で続けるときの見通しです。数字は仮置きで、法律と制度の扱いは専門家と役所に確かめてから決めます。

### お金の回り方
- **本人は無料**。払うのは自治体・社会福祉協議会からの委託（1人あたり月1,800円＋1か所あたり月3万円を仮置き）。家族向けの任意の上乗せ（思い出ばなし・週のまとめ。月480円）は脇役
- 家族の65%は「月1,000円まで」しか払えない（社内アンケート）ので、家族の負担だけでは原価に届かない
- 協力者のマッチングから手数料は取らない（ボランティア。サービスはお金を扱わない）

### 原価
- いまは1人あたり月1,800〜3,300円（毎日3分。アメリカの番号から Twilio）。大半は通話料で、Claude は1回1円未満（[競合調査](./competitive-analysis.md)）
- 日本の電話会社に切り替え、電話を2分ほどに収め、音声認識を見直して、**月1,000〜1,200円**まで下げるのが目標

### 採算（基本の試算）
| 年度 | 市町村 | 利用者 | 年の利益 |
| --- | --- | --- | --- |
| 1年目（雲仙で実証） | 1 | 50人 | −240万円 |
| 2年目（島原半島） | 3 | 400人 | −806万円 |
| 3年目 | 10 | 1,500人 | −1,387万円 |
| 4年目 | 25 | 4,000人 | ＋521万円 |
| 5年目 | 50 | 8,000人 | ＋4,402万円 |

- 黒字になるのは4年目。それまでの赤字の合計は約2,400万円で、補助金・融資・出資で用意する必要がある
- 利用者が半分なら5年では黒字にならない。**原価を下げることと、1か所あたりの利用者を増やすこと**が一番効く

### 始めるまでに越えるハードル
| 重さ | ハードル | 決めること |
| --- | --- | --- |
| 高 | 個人情報（体調の話は特に慎重に扱う情報） | 集める前の同意、家族・協力者への提供の同意、外国の AI・サーバーを使うことの説明と契約 |
| 高 | 認知症の人の同意 | 家族やケアマネジャーと一緒に始める形。成年後見の人の扱い |
| 高 | 日本の電話番号と「知らない番号には出ない」 | 国内の番号を取る。市が配る迷惑電話の防止機器に止められない工夫（電話帳への登録、市・社協の名前での案内） |
| 高 | 緊急のときの責任 | 「緊急通報のサービスではない」と明記。知らせが届かないときの次の連絡先。会社の賠償責任保険 |
| 高 | 協力者が集まるか、続くか | 社協と一緒に集める。1人に頼みすぎない。少ない地区は社協の生活支援サービスにつなぐ |
| 中 | 送迎と道路運送法 | 実費だけにとどめる。地域通貨と組み合わせない |
| 中 | 自治体と契約するためのセキュリティ | プライバシーマークか ISMS。予算は前の年に決まるので、実証から有料の契約まで1年以上 |
| 中 | AIの品質 | 長崎弁の聞き取り、安全テストを200場面に、誤った知らせの割合を測る |
| 中 | 運用の体制 | 毎朝の自動発信、かけ直し、止まったときの連絡、平日の昼に人が出る窓口 |

### 進め方
1. **準備（〜2027年3月）**：雲仙で家族・知人の10人、1か月。関門は「電話に出た割合8割・1か月続いた人8割・緊急の取りこぼし0」
2. **実証（2027年度）**：雲仙市・社協と50〜100人。関門は「3か月続いた人7割・困りごとの成立6割・協力者1人あたり月2件まで・市が翌年度の予算を付ける」
3. **有料の契約（2028年度〜）**：島原半島 → 長崎県 → 九州 → 全国

関門に届かなければ、マッチングの事業としては続けず、社協の道具として渡すなど形を変える。
