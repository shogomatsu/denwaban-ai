# 安全チェックの結果（2026年11月8日）

提出の前に、Claude（Fable 5.1）にコード全体と Git の履歴を読んでもらい、安全上の弱いところがないかを確かめました。読むだけのチェックで、コードは変えていません。

## まとめ

**合言葉を知らない外の人ができることは、ほぼない**、という結果でした。ハッカソンの試作としては丁寧に守られている、という評価です。合言葉を知っている人が悪用したときに起きうることが3つ見つかったので、審査のあとに直します。

## 問題がなかったこと

- **電話の宛先は外から指定できない**：かける相手は環境変数に登録した番号だけ。かかってきた電話も、登録した番号からしか受けない
- **本人の住所・電話番号は、「引き受ける」を押した登録済みの協力者1人にだけ渡る**：状況画面と MCP は、LINE の ID・住所・電話番号を返さない
- **Twilio と LINE から届く知らせは偽物を送れない**：どちらも署名を確かめていて、鍵がないときは必ず断る
- **合言葉と MCP の鍵の比べ方**：比べるのにかかる時間から合言葉を推測されない方法（`timingSafeEqual`）で比べている。MCP の鍵が設定されていなければ、窓口ごと閉じる
- **画面に変な仕掛けを埋め込まれない**：受け取ったデータは文字として表示していて、HTML として読み込まない
- **音声の変換**：ffmpeg に渡す引数は固定。シェルを通さない
- **データの置き場所**：Supabase の全部の表で、行ごとの読み書きの制限（RLS）を有効にしている。読み書きできるのはサーバーの秘密キーだけ。声の保存場所は非公開で、聞くためのアドレスは10分で切れる
- **Git の履歴（52コミット）**：API キー・トークン・LINE の ID・本物の電話番号・`.env` は入っていない

## 審査のあとに直すこと

いずれも、合言葉を知っている人が悪用した場合の話です。審査のあいだに動いている仕組みを壊さないよう、直すのは審査のあとにします。

| 重さ | 内容 | 直し方 |
| --- | --- | --- |
| 中 | 合言葉を何回でも試せる | 失敗が続いたら、しばらく受け付けない。状況画面と「電話をかける」は別の合言葉にし、電話は「10分に1回まで」にする |
| 中 | ブラウザ版は、会話の記録をブラウザが持って毎回送り返すので、細工した記録をそのまま受け取ってしまう | 電話版と同じように、記録をサーバー側に置く。または、受け取った記録からツールの呼び出しを取り除く |
| 中 | 話した言葉が、そのまま家族や協力者への文面に入る | 文の長さに上限を付け、「AI が聞き取った内容です」と添える。安全テストに場面を足す |
| 低 | MCP の鍵をアドレスに入れて渡せる | ヘッダーで渡すのを基本にする。鍵はときどき作り直す |
| 低 | 電話の発信でエラーになったとき、エラーの文に本人の番号がまざることがある | エラーの文から番号を伏せる |

宛先は登録した家族と協力者に限られます。なので、上の3つのどれでも、知らない人に個人情報が漏れるところまではいきません。
